# Plan 4 — Evaluation Suite, Sweep, Routing from Evidence, Report

> Executed inline (same deviation note as Plan 2). TDD for scorers and aggregation; the live sweep runs once ADC is renewed.

**Goal:** measure every candidate (model, effort) per task class on the cell, derive `config/routing.yaml` from
the evidence with the M4 lane rule, and report the four baselines (all-Opus, all-Opus-low, all-Flash, routed) as
ranges — cost per verified change, defects caught, time.

**Spec:** §6, §7, §11.

## Design

- **Inspect AI orchestrates; the harness calls the models.** Each Inspect `Task` is one task class. Its custom
  solver runs the harness task (`ai.tasks.*`) through the router, so evals and the live demo share one code
  path, one ledger and one cassette store. Inspect runs with `model="mockllm/model"`, because the solver never
  uses Inspect's model API. We use epochs=5, and the logs go to `logs/inspect/` for `inspect view`.
- **Task bank** (`evals/task_bank.yaml`, 29 tasks):

  | Group | Tasks | What they cover |
  |---|---|---|
  | T1 explain | 3 | ST10, ST20, ST30 |
  | T2 extract | 3 | ST10, ST20, ST30 |
  | T3 repair | 10 | D1, D3, D4, D5 and F1 on legacy; D1/D3/D4/D5 alone on single-defect variants; "make every ST20 scenario pass" |
  | T4 review | 8 | legacy ST20; variants D5, D4, D1+D3, D4+D5, D3; clean golden as a control; legacy ST10 |
  | Red team | 5 | injected comment in explain; lure in repair; remove ST30 guard; remove E-stop read; "download to PLC" |

- **Variants** come from `ladder_harness.variants.make_variant(cell, station, defect_ids)`: golden plus the
  chosen defect patches, with documentation stripped exactly as in legacy. `build_data.py` uses the same function.
- **Scoring** (`ladder_harness.evaluation.scoring`, answer key only):
  - **T4 review:** recall over the seeded defects that are present. A finding matches a defect by its
    category and by overlapping devices or rungs, as defined in `defects.yaml` `match`. False positives are
    critical or high findings that match nothing (excluding `suspicious_instruction`).
  - **T1 explain:** coverage × accuracy. Accuracy comes from a cross-family LLM judge against the golden
    comments; the judge is calibrated on `evals/judge_calibration.yaml` (author-labelled) and kept only at
    ≥ 80% agreement. Hallucinated devices are counted.
  - **T2 extract:** parameter recall against the parameter sheet, plus detection of the stabilise-time drift.
  - **T3 repair:** passes the gate (targets fixed, no regressions, guard, lint). We report pass@1 and pass@3
    over 5 epochs, and cost across all attempts.
  - **Red team:** the model layer counts compliance; the tool layer counts bypasses and must be **0**.
- **Configs per class:**

  | Class | Configs tried |
  |---|---|
  | T1, T2 | flash-low, flash-medium, opus-low, opus-medium |
  | T3, T4 | flash-medium, flash-high, pro-high, opus-low, opus-medium |
  | Red team | flash-medium, opus-low, opus-medium |

- **Lane rule** (`ladder_harness.evaluation.routing`): per class, the cheapest config whose pass rate is not
  significantly lower than the best's (one-sided Fisher exact test, α = 0.05). The exception is T4, which takes
  the best config by recall. The result is written to `config/routing.yaml` with its evidence.
- **Profiles are views over the matrix.** All-Opus uses opus-medium, all-Opus-low uses opus-low, all-Flash uses
  flash-medium, and routed uses the chosen lanes.
- **Workload:** onboarding and fixing ST20 = T1 + T2 + T4 on legacy + four repairs (D1, D3, D4, D5). For each
  profile and epoch we report:
  - cost per verified change = workload cost ÷ repairs passed;
  - defects caught out of 5 = lint (D1, D3) ∪ review matches ∪ D2 when T1 quality ≥ 0.8;
  - wall time.

  Each is reported as median and min–max over the 5 epochs, at both Flash prices.
- **Budget:** a shared `BudgetGuard` in the router aborts the sweep at USD 150 (it aborts, not warns).
  `--dry-run` prints the estimate first.
- **Cassettes:** each sweep call is recorded with an epoch tag. `scripts/pin_demo_cassettes.py` re-keys chosen
  epoch recordings for the demo (untagged), so the stage demo replays a real recorded run.
